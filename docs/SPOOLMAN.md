# Optional Spoolman integration

The Spoolman integration was added by tharje (#208), got its own switch in #227 and was merged with the tested printer package in #231, where Neme77 validated it against a real Spoolman.

Settings → Integrations → **Enable Spoolman** controls the printer-wide integration. It starts off on a new installation. An existing configured trial without this flag keeps its previous enabled state on migration.

When enabled, Spools shows its Spoolman server settings, and spool forms show the Spoolman link field. Turning it off hides those controls and prevents new server requests. A request already sent may finish; its accounting result is still settled, while remote imports and metadata pulls are not applied while disabled.

URL, proxy credentials, spool links, pending usage and the independent local tracking setting are retained. Usage charged locally while paused stays queued; re-enabling uses the existing reconciliation rules rather than sending unknown-outcome usage twice. Changing the server address or the login no longer throws pending usage away: it goes on the list of usage that was not sent (see below).

The flag persists across browser refreshes and application restarts. It is stored on the printer, not per browser. Exported backups never carry proxy credentials or an enabled integration; restoring a backup does not restart synchronization.

## What the sync does

- **Address.** The server is given as `http://IPv4-address[:port][/path]`, for example `http://192.0.2.5:7912`. A host name (`spoolman`, `spoolman.local`, `localhost`) is refused when it is saved, because the printer never resolves names; there is no TLS either, so `https://` is refused too.
- **Every two minutes** (and right after the integration is switched on) the printer reports the grams it has measured for each linked spool, then reads Spoolman's spool list and imports every Spoolman spool that has no local entry yet. Nothing has to be created by hand.
- **The list is read in pages** of 20 (`GET /api/v1/spool?sort=id:asc&limit=20&offset=…`, with `X-Total-Count` for the end). A page that is too big for the printer's buffer is halved; a spool that cannot be read at all is skipped and counted, the rest is still imported. Archived spools are not asked for, so they are never imported. At most as many spools are imported as the library has room for (128 in all).
- **A linked spool is refreshed from that same list**, without a request of its own. One that is not in the list (archived or deleted in Spoolman) is asked for by itself.
- **What is taken over.** Name, material, colour, maker (as the brand) and remaining weight. The colour is `color_hex` (`RRGGBB`, or `RRGGBBAA` of which only the RGB is kept); a multi-colour filament without `color_hex` takes the first of its `multi_color_hexes`. When an imported spool's Spoolman data has no `remaining_weight`, it is worked out as Spoolman does: the spool's own `initial_weight`, else the filament's `weight`, minus `used_weight`. The full-spool weight is the filament's `weight`; only when the filament has none, the spool's `initial_weight`, else what is left plus what was used; the empty-spool weight (`spool_weight` of the spool, else of the filament, else of the maker) is imported as the tare.
- **Spoolman is the source of truth** for a linked spool: a local change to its name, material, colour, brand or weight is overwritten by the next sync (within two minutes). A weight correction therefore belongs in Spoolman. The tare is only set at import.
- **Spools Spoolman has no weight for** (neither the spool nor its filament has a start weight) are not imported, and are counted in the status. A linked one keeps the weight it has here and still gets its other fields.
- **A material Spoolman does not give** (or one longer than 32 characters) is shown as PLA on import; the status counts them as `no_material`. **A colour Spoolman does not give** is shown grey (`#808080`) on import; the status counts them as `no_colour`. Only six or eight hex digits are a colour; `F00` or `#FF0000` count as none.
- **Time limits.** Each request has 15 seconds in all (the 5 second read timeout restarts with every byte a slow server sends), and a sync cycle starts no new work after 90 seconds. What is already running is finished first (a job is up to three requests of 15 seconds), so a cycle can last about 135 seconds at most. Usage the cycle did not get to is kept for the next one, which starts where this one stopped.

## Usage that was not sent to Spoolman

Usage the sync cannot or must not send by itself is kept on a list on the Spools page, **Usage not sent to Spoolman**. Nothing on it is ever sent automatically: you decide for each entry. An entry has the spool's name, the amount in grams, the date and one of four reasons:

- **Login changed**: the login to Spoolman was changed (the address is the same). The spool is the same, so the amount can be sent to it. If the address is changed later as well, the entry becomes **Server changed**: its number then belongs to the old server.
- **Server changed**: the Spoolman address was changed. The spool is connected to a spool number of the old server, so you choose the matching spool on the new one.
- **Spool not found**: Spoolman answered 404 for the linked spool in two sync cycles in a row (it may have been deleted there), and Spoolman's list of spools answered in each of those cycles. Before, these grams were tried again every two minutes without end; now they wait on the list. One single 404 changes nothing, and any other answer in between (an error, no answer) starts the count again. A 404 counts only while the list answers: a wrong base path, or a proxy that says 404 to everything, therefore never moves a spool's grams onto the list; they stay queued and the status shows the error.
- **Unsure**: the amount was sent, but the answer never arrived and Spoolman's used weight cannot settle it (or a restart came in the middle of the request). Spoolman may already have counted it, so it is never sent a second time; the entry can only be removed.

**Send selected** sends the chosen entries, each to the Spoolman spool chosen next to it (the choice shows name, material and the weight Spoolman shows for the spool), with the same `/use` request and the same check of the used weight as the sync. It is locked while a chosen entry has no spool. A sent entry leaves the list; one that could not be sent stays; one whose answer is lost and cannot be settled becomes *unsure*. **Don't send** (not for *unsure* entries) asks first and then removes the entry; nothing is sent and Spoolman keeps showing the amount as still on the spool. A spool that is connected to Spoolman takes Spoolman's weight over again at the next sync, so its weight on the printer can go back up; only for *Spool not found* does it stay as it is. **Remove from list** is the same for *unsure* entries.

A change of the address that only writes the same server differently (a slash at the end, the default port written out) is not a change of server: nothing moves and nothing is marked. Another host, port or path is.

After a change of the address, a line at the top of the list names the spools that are still connected to the old server. Two buttons decide what happens to them. **Keep connections** is for the same Spoolman under a new address: the spools keep their numbers. **Remove old connections** unlinks them (the spools stay); anything they still had pending goes on the list. Spoolman's own spools that are not connected are then added to this printer as new spools at the next sync, so a spool can appear twice; delete the extra ones. **Until one of the two is chosen, the sync takes nothing over from Spoolman into those spools** (no name, colour, brand or weight) **and sends no usage to Spoolman at all**, because the Spoolman spool with that number may be another one on the new server. Usage that is measured meanwhile is only collected (for every spool, also those imported since): after **Keep connections** it is sent; after **Remove old connections** the amounts of the unlinked spools go on the list and the other spools send theirs. Spoolman's other spools are still imported, and a spool imported after the change of address is not an old connection: **Remove old connections** leaves it linked. Emptying the address and typing one in again counts as a change as well, because the printer cannot know which server the numbers belong to; the question then comes once and **Keep connections** ends it. When the list is opened for the first time after a change of address or login, the page says so once. Turning the sync off (an empty address) is your own decision and puts nothing on the list. At most 32 entries are kept; amounts for the same spool and reason are added to one entry, and a change of the address is refused with a message while the list is full, so such a change cannot push amounts out unnoticed.

Things that are not covered by the list. An amount whose answer was lost and cannot be settled while the list is full is forgotten as before (only the list being full makes that happen). Emptying the address discards the amounts still queued, as before (it is your own decision). Restoring a backup empties the list, and so does going back to a firmware that does not know it (its next save of the spool library leaves it out), so send or remove the entries first. **Send selected** is refused with “Spoolman sync is busy: try again in a moment” while a sync cycle is running, which can take up to about 135 seconds; nothing is lost, press it again.

The list is saved with the spool library on the printer. It is not part of an exported backup (like the other sync accounting), and restoring a backup leaves it empty. `GET /api/spools` carries it as `spoolman_held` and `spoolman_stale_links`; the requests are `POST /api/spoolman/held/send`, `/api/spoolman/held/discard`, `/api/spoolman/unlink-old` and `/api/spoolman/keep-old` (see `cc2-control/docs/API.md`). The list of Spoolman's spools in the choice next to each entry is read in the same pages as the sync; if Spoolman has more than 200 spools, the page says that only the first 200 are listed.

The list of spools and the choice made from it belong to the Spoolman server they were read from. A spool number means a spool only on that server, so when the address or the login changes while the page is open, the page drops the loaded list, the ticks and the chosen spools at once and reads the new server's list; an answer from the old server that arrives late is ignored. The printer checks it as well: **Send selected** carries the generation of the server settings the spools were chosen under (`spoolman_gen` in `GET /api/spools`, `gen` in the catalog) and is refused with a message (nothing is sent, not to the new server either) when the address or the login changed since. Writing the same server differently, or switching the sync off and on, does not change the generation.

## Status

The Spoolman card on the Spools page shows the result as one line under the fields, with a second line that says what to do. It reads `GET /api/spoolman` every 15 seconds while the card is on the page and once after **Save**; the request only reads the printer's memory and sends nothing to Spoolman. The line names, in this order, what stopped the last cycle (`result` other than `ok`), spools in Spoolman without a weight that were not added (`no_weight`), a full spool library (`library_full`), or the time of the last sync; the time is written as date and time, not as "3 minutes ago". There is no line while the integration is off or no address is set. After a change of the address or the login the next cycle starts at once; until it has run, the line says that nothing has been synchronised yet. The note under the address field repeats that only IPv4 addresses work.

`GET /api/spoolman` answers what the last cycle did: when, the result (`ok`, `unreachable`, `unauthorized` for 401, `forbidden` for 403, `not_found`, `server_error`, `refused`, `bad_reply`, `too_large`, `timeout`, `bad_url`, or `never` before the first cycle), the HTTP status if there was one, how many spools have grams waiting to be sent, what the list read (`pages`, `read`, `new`, `unreadable`, `no_weight`, `library_full`, `too_large`, `no_material`, `no_colour`; `read` counts the spools the cycle looked at, and the cycle stops after the page on which the library is full and every linked spool has been seen, so with a full library `read` is far lower than the number of spools in Spoolman and `library_full` counts only the spools seen before it stopped), how many linked spools Spoolman has archived (`archived_linked`; they are still synced) or does not know (`orphaned`, the Spoolman ids; counted only while Spoolman's list answers). Their usage goes on the list of unsent usage after the second cycle in a row. A line is written to the log when the result or the orphaned set changes, never one per cycle, and never the address or the login.
