# Community Firmware V4.3 — release candidate

This candidate includes all merged work through PR97 (filament inventory and
spool tracking), plus the experimental O0 callback runtime integration.
CC2 Control uses `VERSION`; firmware uses `FIRMWARE_VERSION`. The builder reads
the same values from its pinned source archive. No second runtime version is
maintained in scripts.

## Why include the callback runtime?

The published ELEGOO reactor implementation retains callbacks registered for
webhook requests. Their captured requests and connections can remain alive.
The request log also grows without a bound. Repeated socket requests can
therefore contribute to memory degradation during long printer sessions.

See the [ELEGOO source issue](https://github.com/elegooofficial/CentauriCarbon2/issues/12)
and the [qualified runtime evidence](../experimental/combined-test/VALIDATION.md).
The community's reduced UDS polling, contributed by beanbo, remains included.
The callback runtime additionally changes callback/timer/poll/wait handling
for one exact fingerprinted printer executable. **It does not bound the
vendor request log or guarantee that every OOM/803 cause is resolved.**

Previous builds have encouraging user-reported long prints, near-stable
available memory, successful homing and persistent activation after reboot.
These reports are not controlled A/B measurements, and they do not validate
this new complete firmware image. The latest spool feature also needs hardware
testing in this candidate.

The runtime is experimental and provisional. Public ELEGOO sources predate the
deployed firmware, so rebuilding that published executable would lose later
vendor changes. Reassess or retire this runtime when matching sources or a
verified official correction become available; no vendor fix date is promised.
O0 is mandatory: O1 reproduced a floating-point/coroutine regression with the
native libco during qualification.

## Included improvements

- Reduced socket traffic and persistent UDS telemetry.
- Asynchronous bounded analysis of large G-code files, preserving HTTP/UDS
  responsiveness, with cache invalidation and corrected HTTP request deadlines.
- Build-plate library, mesh and side A/B management and control-page alignment.
- Hotend/bed PID calibration and configuration saving.
- Temperature target changes during active or paused prints.
- Native printer error reporting with historical-event popup suppression.
- CC2 startup 30 seconds after the vendor process appears.
- Filament inventory and spool tracking from measured extrusion (PR97).
- Current interface, five languages, camera ownership, print history, slicer
  integrations and existing community features.

Credits remain with the original contributors, including Surfoo's interface,
localization and version management, beanbo's telemetry/UDS work and DamiBFryta's
testing. Existing source and third-party notices remain included.

## Two installation routes

1. **Complete firmware:** a signed `.zip.sig` generated by the builder, using
   the existing qualified stock/private inputs. The firmware installs an
   immutable runtime payload and seeds the qualified persistent runtime path
   at boot. Exact vendor/libco hashes and native bridge preflight gate
   activation. Missing/incompatible inputs or a failed preflight start the
   vendor executable without the module. The normal vendor launch keeps
   `LD_BIND_NOW=1` and its arguments.
2. **Standalone updater:** `CC2-Control-<VERSION>-Callback-O0-Update.zip`, generated
   in the repository's `output/`. This updates CC2 and adds the persistent
   callback without reflashing the firmware. It uses the established cold/idle
   compatibility, activation and rollback checks. It refuses an already active
   runtime: restore the existing experiment with that printer's own recorded
   backup before applying it. A reboot alone does not remove that experiment.

The complete image and standalone updater are built with byte-identical CC2
and callback components; the release driver checks that equality. Firmware
boot integration differs from standalone activation and needs separate tests.
Configuration, material presets, UI preferences and the spool inventory are
persistent. The standalone rollback preserves the current spool inventory.

## Disable the firmware-integrated experiment

At idle, create `/opt/usr/cc2-reactor-disabled`, then reboot. The firmware's
callback hook starts the vendor executable without this module. To re-enable,
remove that file and reboot at idle. Verify maps, the current PID marker, MQTT
and fresh UDS after each change. This switch applies to the complete firmware
integration; the standalone updater is removed using its own backup/restore.
An old activation marker is not proof of current activation.

When this firmware replaces an earlier standalone runtime, its old directory
is retained as `cc2-reactor-before-firmware-<PID>`. Do not run that experiment's
restore script against changed firmware launch files. Keep the prior firmware
release for full rollback and preserve the printer configuration backup.

## Build and release status

Extract this kit into a new directory. Supply the previous builder directory
when running `builder/current/Build-Release.ps1`; it copies only the known local
inputs, never prepared components or source. Existing signing/input hashes
remain mandatory. Qualified ARM GCC 6.5.0/glibc 2.23 and pinned SquashFS 4.6.1
are required. The same driver can build only the standalone updater.

This is a **candidate, not an already built or hardware-validated firmware**.
Signed firmware, ARM binaries and checksums become real release assets only
after the owner's build succeeds. No private keys or vendor firmware are in
this source kit. Before publication, record the actual firmware hash and test
installation, reboot, callback maps/PID, UDS, homing, PID, temperatures, plate
management, large files, spool tracking and a supervised print. See
[TESTING.md](TESTING.md). Do not label prior-image tests as tests of this image.
